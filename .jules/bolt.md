## 2024-05-24 - Precomputing Shapely Polygons in NMS
**Learning:** In NMS algorithms that rely on Shapely for `poly_iou` calculation, recalculating `Polygon` objects and doing complex set operations like `.buffer(0.0001)` inside an O(N^2) double loop is extremely slow. Buffering adds vertices and makes intersection vastly slower, negating any caching benefits.
**Action:** When optimizing Shapely geometric intersections in inner loops (e.g., `poly_nms`), avoid pre-buffering polygons for intersection, as this drastically reduces performance. Use `poly_A.intersection(poly_B)`. If highly irregular OCR polygons cause errors during intersection, wrap the specific call in a `try...except Exception:` block to fall back to an unoptimized helper function (e.g., `boundary_iou`), rather than trying to import and catch version-specific errors.
