## 2024-05-24 - Pre-computing Shapely objects and preserving backward compatibility in poly_nms
**Learning:** `poly_nms` previously suffered from O(N^2) overhead because it repeatedly constructed `Polygon` objects and performed expensive intersection operations within a nested loop. However, when optimizing `poly_nms` or geometric union calculations with Shapely, adding indiscriminate buffering inside shared helper functions like `poly_intersection` or `poly_union` causes errors or massive performance regressions. Furthermore, using buffered polygons to calculate the union area drops polygons erroneously, breaking backward compatibility.
**Action:** When dealing with Python arrays and Shapely geometries in NMS, pre-compute `Polygon` objects and their buffered forms in O(N). Crucially, wrap the pre-computation itself in a `try...except Exception` block to catch errors from degenerate polygons. Inside the hot loop, inline the intersection area and union logic to process the pre-computed polygons and avoid function call overhead. Use the *unbuffered* area (`poly.area`) alongside the buffered intersection to calculate the union area. This ensures exact backward compatibility and perfectly mirrors the original `poly_union` logic without dropping polygons erroneously, effectively preventing result count mismatches during IoU caching.
