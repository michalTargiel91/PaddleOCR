## 2023-10-24 - Precomputing Shapely polygons in PaddleOCR poly_nms
**Learning:** `poly_nms` dynamically recreates Shapely polygons in an O(N^2) loop using `points2polygon(A)` leading to excessive redundant calculations and severe bottlenecks (~1.5s down to 0.1s for N=100). The loop directly called `boundary_iou` which instantiated polygons repeatedly. Extracting the list of Shapely `Polygon` creation out of the nested loop reduces calculation time by ~93%. However, we must ensure properties like `buffered` polygons and `area` are precomputed cleanly to handle the full `poly_iou` requirements inside the loop. Valid geometries must also be handled properly using a `try..except` block or fallback mechanisms to prevent NameErrors on invalid detection boundaries.
**Action:** When inspecting O(N^2) bounding-box or IOU loops in ML/OCR post-processing, look for redundant geometric conversions (e.g., list/numpy to Shapely objects). Precompute them in O(N) before the main loop. Maintain original fallback behaviour (like substituting area for 0.0 on exception).
